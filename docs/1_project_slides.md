# OUR CHALLENGE
## Conversational Access to Robot Documentation

Build a system that transforms buried documentation into **accurate, clear, and source-grounded answers**.

---

## 1. THE PROBLEM

### Every robot comes with a lot of documentation

- `PDF / user-manual.pdf`
- `PDF / datasheet.pdf`
- `PDF / product-sheet.pdf`
- `PDF / specifications.pdf`
- `PDF / accessories-guide.pdf`

**The answer is in there.**

### YOUR MISSION

Make the answers easy to find.

---

## 2. STARTING DATA

### Starting Kit: What the Documents Cover

- Technical documentation
- Product sheets
- Specifications
- Functional features
- Usage details

## 3. THE CHALLENGE

Turn this documentation into a system anyone can talk to.

### WHO YOU'RE BUILDING FOR

**Two users, one system.**

| Technicians | Non-Technical Users |

| "What's the value of this parameter?" | "Which robot fits my customer's needs?" |

Both need answers that are:

- Accurate
- Clear
- Grounded in the data

## 5. HOW WE JUDGE

Your solution will be evaluated based on:

- Quality of the answers
- Ease of use
- Faithfulness to the source

### REQUIRED: At Least One Working Interface

Whatever you build must reach real people.

End users must be able to:

1. Ask a question.
2. Get an answer.

**END USER → YOUR SYSTEM → ANSWER**

---

## 6. BONUS CHALLENGES

### BONUS 01 — Plug-and-Play Retrieval

Keep your retrieval engine separate from the interface and expose it so that other frontends can use it too.

**Example architecture:**

- API
- Retrieval Engine
- Web App
- Chatbot
- Voice Assistant
- Existing Tool

### BONUS 02 — Speaks Many Languages

Allow users to ask questions and receive answers in their own language, even when the source documentation is written in another language.

**The goal:**

- Ask in your language.
- Source in another language.
- Receive a coherent answer.
